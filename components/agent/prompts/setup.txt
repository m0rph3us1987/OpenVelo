## Instructions

Use your tools to analyze the build and/or test output.
1. Determine if the error is caused by missing build/test tools, libraries, or dependencies (e.g., "command not found", missing header files, missing libraries, "dotnet: not found", "npm: not found", "cannot find module", package/module import errors).
2. Determine if the error is due to missing project files (e.g. "package.json not found", "no such file or directory pom.xml", "no sln file").
3. Determine if the error is an actual logic or syntax error in the code (e.g., compilation errors, syntax errors, "ReferenceError" unrelated to missing imports, failed assertions, failing business logic tests).

If the error is due to missing tools, libraries, or dependencies:
- Update the setup script at {{SETUP_SH_PATH}} to install or restore the missing tools or dependencies.
- Ensure the setup script contains appropriate package manager installation/restoration commands (e.g. `npm install`, `npm ci`, `yarn install`, `pnpm install`, `pip install -r requirements.txt`, `pip install -e .`, `dotnet restore`, `mvn install`, `go mod download`, etc.) based on the project type, so that all project dependencies are fully restored.
- The script must be non-interactive (use `export DEBIAN_FRONTEND=noninteractive`, `apt-get install -y`, etc.).
- You MUST prepend `#!/bin/bash` to the script if it's new.

If the project is empty of build/configuration files (e.g. package.json, pom.xml, go.mod is missing) and the build command fails because of this, AND the story is about scaffolding/initializing the project/structure.

If the error is an actual code error or build/test logic error that cannot be fixed by installing tools or restoring dependencies:
- Do NOT adjust the setup script.

## CRITICAL: How to report your decision

You MUST use your file writing tool to create the file `{{VERDICT_PATH}}` containing EXACTLY one of the following four strings on a single line, with no other text, no analysis, no explanation, no markdown formatting:

```
SETUP_OK
SETUP_ADJUSTED
BUILD_ERROR
EMPTY_PROJECT
```

Choose:
- `SETUP_OK` — the build and tests pass; no setup script change needed.
- `SETUP_ADJUSTED` — you edited `{{SETUP_SH_PATH}}` to fix a missing tool/dependency; re-run setup.
- `BUILD_ERROR` — the failure is an actual code/logic error that cannot be fixed by installing tools or restoring dependencies.
- `EMPTY_PROJECT` — the repository has no build/config files and the story is about scaffolding.

The file `{{VERDICT_PATH}}` is the ONLY signal the workflow reads. Your assistant response text (or reasoning text) is ignored. If `{{VERDICT_PATH}}` is missing, contains no valid verdict, or contains any extra text, the workflow will fail.
